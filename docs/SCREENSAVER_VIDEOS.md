# 视频屏保

控制中心 → 个性化 → 屏幕保护程序 →「视频」。用手机扫描同一页的二维码，在手机页选「视频」后添加 MP4 或 MOV；可以多选，逐个上传。上传不会替用户选择屏保，也不改变壁纸。

影片保存在电视本机，静音、随机排列后循环播放；左右键切上一段、下一段，其他键唤醒。没有影片，或所有影片都打不开时，回退到照片屏保。手机页可以逐段删除。

建议 1080p H.264，兼容 Android 5.0 起的电视。其他编码取决于电视自己的解码器；不在电视上转码。每段上限 200 MiB，共 512 MiB，最多 64 段。大批上传时电视只需要为当前一段保留临时空间。

## 史努比素材示例

[hitnology/snoopy 0.2.2](https://github.com/hitnology/snoopy/releases/tag/0.2.2) 是 macOS 屏保。发布包的 Resources 中有 tvOS 26 的 12 段完整录屏，也有需要 Apple HEVC 透明通道的旧分层影片。Android 的普通 HEVC 播放器不能还原后者的透明通道。

自行取得该发布包后，可以用下面的工具将 12 段录屏转成无声的 1080p H.264，再通过手机页导入。需要 Python 3.8+ 和 PATH 中的 FFmpeg；输出目录必须尚不存在。

```sh
python tools/prepare-snoopy.py snoopy.saver.zip snoopy-mp4
```

工具只处理 0.2.2 中确认的 12 个录屏文件（`101_AS003`、`101_AS004`、`101_AS007`–`101_AS016`），不自动下载、上传或分发素材。录屏开头的箭头仍会保留。四个旧 AS 文件和 Intro/Loop/Outro、遮罩等分层素材没有包含在这次适配中；不是 macOS 播放器的完整移植。

## 实现

- `ScreensaverVideos` 管理应用私有目录 `files/screensaver-videos/`。上传先校验是否有视频轨和时长，再复制到暂存目录、原子改名发布；总容量、单段大小和数量均有限制，删除只接受本库生成的 ID。
- `VideoSaver` 使用 Media3、本地文件和一个有界缓冲的播放列表。影片打不开或 8 秒仍不能播放，就从本轮队列移走；不会因为解码失败删除用户文件。退出屏保会释放播放器。
- 桌面空闲屏保和 `AerialDream` 复用同一个组件，沿用现有左右切片、返回键和空闲计时。
- APK 中只有代码和五种语言的界面文字，不含动画。素材通过手机页原有的本地令牌地址导入。

## 验证

KKTV U86V9 / Android 9 上用并行 release 包预编译后测试：12 段转好的 H.264 影片均通过手机页导入，抽查播放、自动进入下一段、左右切片、确认键唤醒回到主页；从手机页删除本次导入的影片后，空列表回退到照片，再重新导入成功。电视的「视频 / 立即开始」入口可用。中、英、俄、乌、哈五种手机页在 390px 宽度下无横向溢出。

standard / guard release 和 17 项 JVM 测试通过（其中 6 项验证导入与存储边界）。系统级 Dream、其他电视解码器、长时间循环及待机唤醒未在真机验证；不代表所有 MP4/MOV 或 HEVC 透明素材都能播放。
